# Files

- [Artifacts and the file boundary](artifacts-and-file-boundary.md) - How files leave and enter dtcc-agent. Tools write renders and exports into a private per-Session folder and return a name, never a path; the chatbot serves them at /artifacts; run_operation refuses every file-path parameter; load_geojson reads only the shared results folder.
- [Disk cache](disk-cache.md) - The persistent pickle and JSON-index cache for the two dataset downloads (buildings and point clouds). It serves a smaller area from a containing download, cropped with Core's own containment test on each building's source_bounds so the result matches a fresh download, starts cold after a Core upgrade, evicts by TTL and size, and is shared across Sessions. Builder results are measured, not cached.
- [Dispatch, object references and serialization](dispatch-and-object-store.md) - How run_operation resolves parameters, calls a dtcc-core function or dataset, stores the result in the calling Session's ObjectStore under a short ID, and returns an LLM-sized summary, plus the object tools built on that store.
- [Operation catalogue](operation-catalogue.md) - How registry.py reflects over the pinned dtcc-core into a catalogue of named Operations with parameter schemas, built once per process (HTTP at startup, stdio on first use), failing loudly on a broken Core, with dtcc-sim datasets joining later from a background retrier.
